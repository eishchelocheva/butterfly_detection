# Создание проекта через API

Все команды — из корня репозитория. Скрипт создаёт проект, навыки и **пустые закрытые пулы**. Задания загружаются, проверяются и запускаются вручную.

## Команды

```bash
# План без сети и токена
python3 bbox/create_project.py --with-training

# Создание: сначала заполните api_token в bbox/configs/api.json
python3 bbox/create_project.py --apply
```

По умолчанию создаются экзамен, пилот и основной пул. Для обучения добавьте `--with-training` **при первом создании**.

Инструкция берётся из [annotator.html](../instructions/annotator.html). Редактируйте HTML напрямую; дополнительная установка библиотек не нужна.

## Все опции

| Опция | Назначение / по умолчанию |
|---|---|
| `-h`, `--help` | Показать справку |
| `--apply` | Создать ресурсы через API; без флага только план |
| `--with-training` | Добавить оплачиваемое обучение с ручной проверкой |
| `--config PATH` | Настройки: `bbox/configs/api.json` |
| `--interface PATH` | Интерфейс: `bbox/configs/interface.json` |
| `--lock PATH` | Версии интерфейса: `bbox/configs/interface.lock.json` |
| `--instructions PATH` | HTML-инструкция; по умолчанию `bbox/instructions/annotator.html` |
| `--examples-base-url URL` | Публичный HTTPS-каталог с готовыми JPEG из `bbox/instructions/examples/` |
| `--auth-scheme OAuth\|ApiKey` | Способ авторизации; по умолчанию `OAuth` |
| `--state PATH` | Журнал с ID: `bbox/results/api_state.json`; родительская папка должна существовать |
| `--adopt ROLE=ID` | Подтвердить уже созданный объект после сбоя; только вместе с `--apply` |

Токен задаётся в поле `api_token` файла [api.json](api.json). По умолчанию оно пустое: план работает без ключа, для `--apply` нужен ключ. При `--config PATH` ключ читается из указанного файла.

## Настройки api.json

| Поле | Значение |
|---|---|
| `api_token` | Ключ API Яндекс Заданий; по умолчанию `""` |
| `deployment_key` | Постоянное имя запуска; используется в названиях навыков |
| `public_name` | Название проекта для исполнителя |
| `public_description` | Краткое описание проекта |
| `will_expire` | Дата окончания пулов, ISO 8601 с часовым поясом; сейчас `2026-12-01T00:00:00Z` |
| `assignment_max_duration_seconds` | Время на страницу: `1200` секунд |
| `auto_accept_period_day` | Срок ручной проверки до автоприёмки: `7` дней |
| `admission_score` | Минимальный навык экзамена для пилота и основного пула: `90` |
| `training_admission_score` | Минимальный навык обучения для экзамена: `90`; действует с `--with-training` |

В каждом блоке `training`, `exam`, `pilot`, `main`:

| Поле | Значение |
|---|---|
| `tasks_per_assignment` | Число фото на одной странице |
| `reward_per_assignment` | Оплата страницы в рублях |
| `overlap` | Сколько раз размечается каждое фото; не лимит числа исполнителей |

Только в `main` есть необязательный блок `fast_answers`:

| Поле | Значение |
|---|---|
| `min_seconds` | Быстрая сдача — страница быстрее `20` секунд |
| `count` | Ограничить доступ после `2` быстрых страниц в этом пуле; не обязательно подряд |
| `ban_days` | Срок ограничения доступа к основному пулу: `1` день |

Удалите `fast_answers` или задайте `null`, чтобы отключить правило при создании. Отсчёт ведёт Яндекс; уже присланные ответы правило не отклоняет. Порог времени подберите по пилоту.

Для уже созданного основного пула добавьте в кабинете правило **Контроль качества → Быстрые ответы**: минимальное время — 20 секунд, количество быстрых ответов ≥ 2, действие — приостановить доступ к пулу на 1 день. Поле «Учитывать последних страниц заданий» оставьте пустым. Изменение `api.json` существующий пул не обновляет.

## Состояние запуска

На первом `--apply` создаются новые ресурсы и файл `bbox/results/api_state.json`. Повтор той же команды использует сохранённые ID. Пулы остаются закрытыми; загрузку заданий и открытие выполняйте в кабинете.

Сохраните state после создания. Изменённые настройки или инструкция вызывают ошибку fingerprint: скрипт не редактирует существующие проекты. Для ещё одного проекта задайте новый `deployment_key` и отдельный, пока не существующий `--state`.
