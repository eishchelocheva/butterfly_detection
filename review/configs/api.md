# API проекта ревью

Команды выполняются из корня репозитория. Скрипт создания использует общие функции `bbox/create_project.py` и клиент `bbox/tasks_api.py`. Создаются проект, навыки и **пустые закрытые пулы**: загрузка заданий, проверка и открытие пулов выполняются вручную.

## Создание проекта

```bash
# План без сетевых запросов и токена
python3 review/create_project.py

# План с дополнительным обучением
python3 review/create_project.py --with-training

# Создание ресурсов после настройки токена
python3 review/create_project.py --apply
```

По умолчанию план включает экзамен, пилот и основной пул. `--with-training` добавляет обучение и отдельный навык; этот параметр нужно выбрать при первом создании.

| Опция | Назначение |
|---|---|
| `-h`, `--help` | Показать справку |
| `--apply` | Создать ресурсы через API; без флага формируется только план |
| `--token TOKEN` | API-токен; имеет приоритет над `api_token` в конфигурации |
| `--with-training` | Добавить оплачиваемое обучение с ручной проверкой |
| `--config PATH` | Настройки; по умолчанию `review/configs/api.json` |
| `--interface PATH` | Шаблон; по умолчанию `review/configs/interface.json` |
| `--lock PATH` | Версии компонентов; по умолчанию `review/configs/interface.lock.json` |
| `--instructions PATH` | HTML-инструкция; по умолчанию `review/instructions/annotator.html` |
| `--examples-base-url URL` | Публичный HTTPS-каталог с готовыми картинками инструкции |
| `--auth-scheme OAuth\|ApiKey` | Схема авторизации; по умолчанию `OAuth` |
| `--state PATH` | Журнал создания; по умолчанию `review/results/api_state.json`; родительская папка должна существовать |
| `--adopt ROLE=ID` | Подтвердить ранее созданный объект после неоднозначного сбоя; только с `--apply` |

По умолчанию рендерер инструкции использует `bbox/instructions/examples.json` и изображения-источники с рамками в HTML. При `--examples-base-url` используются готовые картинки из указанного каталога.

## Настройки api.json

Токен задаётся в поле `api_token` выбранного файла конфигурации. По умолчанию поле пустое; не отправляйте заполненный файл в Git. Для отдельных настроек используйте `--config PATH`.

| Поле | Значение по умолчанию |
|---|---|
| `deployment_key` | `butterfly-review-2026-v1`; используется в именах навыков |
| `public_name`, `public_description` | Название и описание задания ревью |
| `will_expire` | `2026-12-01T00:00:00Z`; время окончания пулов |
| `assignment_max_duration_seconds` | 1200 секунд на страницу |
| `auto_accept_period_day` | 7 дней до автоприёмки |
| `admission_score` | 90 баллов экзамена для пилота и основного пула |
| `training_admission_score` | 90 баллов обучения для допуска к экзамену при `--with-training` |

| Этап | Фото на странице | Оплата страницы, ₽ | Перекрытие |
|---|---:|---:|---:|
| `training` | 5 | 3 | 10 |
| `exam` | 10 | 6 | 10 |
| `pilot` | 5 | 3 | 2 |
| `main` | 5 | 3 | 1 |

Эти параметры скопированы из bbox как отправная точка. Перед созданием проверьте срок, оплату, перекрытие и пороги для задачи ревью.

### Быстрые ответы

В `main.fast_answers` заданы `min_seconds: 20`, `count: 2`, `ban_days: 1`: после двух страниц, сданных быстрее 20 секунд, доступ к основному пулу ограничивается на один день. Страницы не обязаны идти подряд; ответы автоматически не отклоняются. Чтобы выключить правило при создании, удалите `fast_answers` или установите `null`. Порог следует проверить по пилоту.

Изменение конфигурации не обновляет уже созданный пул.

## Выгрузка ответов и подготовка заданий

```bash
# Список пулов всех проектов или одного проекта; вывод — JSONL
python3 review/tasks_api.py pools
python3 review/tasks_api.py pools --project-id PROJECT_ID

# Ответы из одного или нескольких пулов первичной разметки
python3 review/tasks_api.py prepare --pool-id BBOX_POOL_ID --pool-id SECOND_POOL_ID --review-pool-id REVIEW_POOL_ID --out review/results/bbox_export_01

# Результаты одного или нескольких пулов ревью
python3 review/tasks_api.py download-review --pool-id REVIEW_POOL_ID --out review/results/review_export_01
```

Общие параметры `tasks_api.py` указываются **до подкоманды**: `--config PATH`, `--token TOKEN` и `--auth-scheme OAuth|ApiKey`. Токен из `--token` имеет приоритет над конфигурацией. Например:

```bash
python3 review/tasks_api.py --config /path/to/local-config.json pools --project-id PROJECT_ID
```

У `prepare` обязательны один или несколько `--pool-id` и новый каталог `--out`. Параметр `--input CSV` задаёт канонический список `photo_id,image_url`; по умолчанию используется `data/bbox_input_all_400.csv`.

В каталог выгрузки записываются:

- `bbox_answers.jsonl` — проверенные структурно ответы из выбранных пулов;
- `selected_answers.jsonl` — по одному ответу на фото, с ID исполнителя и временем;
- `manifest.json` — количество и спорные случаи;
- `review_tasks.jsonl` — задания API с `input_values`, `unavailable_for` и, при указанном ID, `pool_id`;
- `review_tasks.tsv` — входы `INPUT:photo_id`, `INPUT:image_url`, `INPUT:boxes`.

Оба файла заданий создаются, если нет выбранных ответов с ошибкой загрузки.

Выбирается первый по `submitted` ответ среди `SUBMITTED` и `ACCEPTED`. При равном времени используются идентификаторы для стабильного выбора. `REJECTED` не включается. Если выбран `load_error`, исходные ответы, выборка и manifest сохраняются, но JSONL и TSV заданий не создаются и команда завершается с кодом 2. `uncertain` отмечается в manifest; имеющиеся рамки передаются в TSV.

`download-review` сохраняет все ответы `SUBMITTED` и `ACCEPTED` в `review_answers.jsonl`, включая входные и выходные значения, ID исполнителя, задания и страницы, пул и время. Выходной каталог должен быть новым: существующие результаты не перезаписываются.


### Скачать результаты готовых заданий review по ID пула

Из корня репозитория выполните в zsh:

```bash
read -r "REVIEW_POOL_ID?ID пула review: "
read -rs "YANDEX_TASKS_TOKEN?OAuth-токен Яндекс Заданий: "
echo

python3 review/tasks_api.py \
  --token "$YANDEX_TASKS_TOKEN" \
  download-review \
  --pool-id "$REVIEW_POOL_ID" \
  --out review/results/review_export_01

unset YANDEX_TASKS_TOKEN
```

Итоговые рамки и вердикт находятся в `output_values.boxes` и `output_values.review_verdict` каждой строки `review_answers.jsonl`. Для нескольких пулов повторите `--pool-id`; для повторной выгрузки выберите новый каталог. Выгрузка содержит ID исполнителей: не публикуйте её. Токен, переданный через `--token`, может быть виден другим процессам на компьютере.


## Формат проекта и ограничения

Входы: `photo_id` (строка), `image_url` (URL), `boxes` (JSON). Выходы: `review_verdict` (`approve`, `reject`, `uncertain`), `status` (`objects`, `empty`, `uncertain`), `boxes` (JSON), `comment` (строка). Редактор, входные рамки и горячие клавиши проверяются в предпросмотре; действие ограничений следует проверять в настройках созданных заданий.

**Самопроверка:** файл `review_tasks.jsonl` содержит `unavailable_for` с авторами полученных ответов на соответствующее фото. Ограничение применяется при создании заданий через API с этим свойством. Действие запрета при загрузке TSV не проверено; скрипт не загружает задания автоматически.

## Состояние создания

При `--apply` используется отдельный `review/results/api_state.json`. Повтор с тем же планом сверяет сохранённые ID; при изменении плана скрипт не обновляет созданные ресурсы. При неизвестном результате POST проверьте объект и продолжайте через `--adopt ROLE=ID`. Не используйте state от bbox и сохраняйте журнал для продолжения работы.

### API-задания с запретом самопроверки

`prepare` формирует `review_tasks.jsonl`: каждый объект содержит `input_values`, `pool_id` и `unavailable_for`. В список включаются все авторы ответов `SUBMITTED` и `ACCEPTED` по этому фото из указанных пулов, а не только автор первого выбранного ответа. Без `--review-pool-id` поле `pool_id` отсутствует, и его нужно добавить до создания заданий через API. Входные данные из JSONL предназначены для вызова API создания заданий; автоматической загрузки этот скрипт не выполняет. Используйте все пулы с разметкой фотографии, иначе авторы из неуказанных пулов не попадут в список исключений. После загрузки проверьте `unavailable_for` у созданных заданий.

Не вводите токен в команду как литерал: значение может попасть в историю оболочки. Передавайте его через переменную окружения, например `--token "$TASKS_API_TOKEN"`. Аргументы процесса могут быть видны другим процессам на компьютере.

**Загрузка TSV:** текущий файл содержит только входные данные и не задаёт ограничение самопроверки. Для ограничения доступа используйте `unavailable_for` в API-заданиях из JSONL. Загрузчик отклонил заголовок `UNAVAILABLE_FOR`; корректный формат TSV пока не установлен.

## Подготовленные данные

В `review/configs/exam.tsv` и `review/configs/exam.tasks.jsonl` находятся 10 экзаменационных заданий; у двух фотографий рамки заменены случайными. JSONL содержит исключения, но не содержит целевой ID пула. Правильные вердикты для автоматической оценки не подготовлены.

В `review/results/bbox_main_export_01/` сохранены 420 ответов, 400 выбранных фотографий, две отметки `uncertain`; подготовленный JSONL и manifest ссылаются на пул `6873090`. `review/tasks_api.py` не выполняет POST загрузки.

Исходные TSV-выгрузки экзамена и основного пула сохранены в `review/results/` и включены в репозиторий. В них присутствуют идентификаторы исполнителей. Дополнительные рабочие выгрузки API могут храниться отдельно.
