# Проект ревью

Подробные настройки и команды API: [configs/api.md](configs/api.md).

Команды выполняются из корня репозитория:

```bash
python3 review/create_project.py
python3 review/create_project.py --with-training
python3 review/create_project.py --apply
```

Без `--apply` скрипт формирует план без сети. С `--apply` он создаёт проект, навыки и пустые закрытые пулы; задания загружаются, проверяются и пулы открываются вручную. Настройки по умолчанию скопированы из bbox как отправная точка; до запуска согласуйте стоимость, перекрытие, срок и допуск. В основном пуле включено ограничение доступа на 1 день после двух страниц, сданных быстрее 20 секунд. Порог времени следует проверить по пилоту.

Файлы: `configs/api.json`, `configs/interface.json`, `configs/interface.lock.json`, `instructions/annotator.html`. По умолчанию инструкция использует общий генератор из `bbox` и `bbox/instructions/examples.json`; `--examples-base-url` задаёт публичную HTTPS-папку с готовыми картинками. Компоненты и версии шаблона, отображение входных рамок и горячие клавиши необходимо проверить в предпросмотре.

Доступны параметры `--config`, `--interface`, `--lock`, `--instructions`, `--examples-base-url`, `--with-training`, `--auth-scheme`, `--state` и `--adopt ROLE=ID`. Для `--apply` передайте `--token` или настройте `api_token`; не добавляйте секрет в Git. Журнал по умолчанию — `review/results/api_state.json`; не используйте state проекта bbox. При изменении настроек существующий проект не обновляется. При неизвестном результате создания следуйте механизму `--adopt`, описанному в `bbox/configs/api.md`.

Вход: `photo_id`, `image_url`, `boxes`. Выход: `review_verdict`, `status`, `boxes`, `comment`. Для переноса исходной разметки нужны подготовленные задания.

**Самопроверка:** `prepare` формирует API-задания с `unavailable_for`, исключая авторов ответов из выбранных пулов. Поле `unavailable_for` предусмотрено API; синтаксис соответствующего столбца TSV пока не установлен и требует проверки.

## Выгрузка и подготовка review

Скрипт только читает API. Токен можно передать через `--token` до подкоманды или задать в файле конфигурации; не отправляйте его в Git.

```bash
python3 review/tasks_api.py pools --project-id PROJECT_ID
python3 review/tasks_api.py prepare --pool-id BBOX_POOL_ID --pool-id SECOND_POOL_ID --review-pool-id REVIEW_POOL_ID --out review/results/bbox_export_01
python3 review/tasks_api.py download-review --pool-id REVIEW_POOL_ID --out review/results/review_export_01
```

`pools` печатает JSONL; `--project-id` необязателен. Для `prepare` можно повторять `--pool-id`; необязательный `--input` указывает CSV с каноническими `photo_id,image_url`, по умолчанию — исходный датасет bbox. Результат: `bbox_answers.jsonl` со всеми полученными ответами, `selected_answers.jsonl` с первым ответом на фото, `manifest.json`, `review_tasks.jsonl` для создания заданий через API и `review_tasks.tsv` с входными данными. Выбор производится по времени `submitted` среди `SUBMITTED` и `ACCEPTED`; при совпадении времени — по идентификаторам. Отклонённые ответы не используются. Если первый ответ имеет статус `load_error`, выгрузка и manifest сохраняются, но файлы заданий JSONL и TSV не создаются: такой ответ необходимо разобрать, а не считать отсутствием объектов. `uncertain` передаётся с имеющимися рамками и отмечается в manifest.

`download-review` сохраняет `review_answers.jsonl` со всеми выполненными или принятыми ответами; входные и выходные значения, ID исполнителя и страницы, время и пул сохранены. Выходные каталоги должны быть новыми. Команды не загружают задания и не открывают пулы. Выбор только первого ответа не является проверкой качества; для запрета самопроверки используйте API-задания из `review_tasks.jsonl`, а не один только TSV.

### API-задания с запретом самопроверки

`prepare` формирует `review_tasks.jsonl`: каждый объект содержит `input_values` и `unavailable_for`, а при указанном `--review-pool-id` также `pool_id`. В список включаются все авторы ответов `SUBMITTED` и `ACCEPTED` по этому фото из указанных пулов, а не только автор первого выбранного ответа. Без `--review-pool-id` поле `pool_id` отсутствует, и его нужно добавить до создания заданий через API. Входные данные из JSONL предназначены для вызова API создания заданий; автоматической загрузки этот скрипт не выполняет. Используйте все пулы с разметкой фотографии, иначе авторы из неуказанных пулов не попадут в список исключений. После загрузки проверьте `unavailable_for` у созданных заданий.

Пример одного задания при указанном `--review-pool-id`:

```json
{
  "pool_id": "REVIEW_POOL_ID",
  "input_values": {
    "photo_id": "123",
    "image_url": "https://example.org/photo.jpg",
    "boxes": []
  },
  "unavailable_for": ["worker_1", "worker_2"]
}
```

Здесь `worker_1` и `worker_2` — примеры идентификаторов авторов первичных ответов; в реальном файле подставляются идентификаторы, полученные из API. Отклонённые ответы `REJECTED` в выборку и список исключений не входят.


Для `create_project.py` и `tasks_api.py` токен можно передать через `--token "$TASKS_API_TOKEN"`; аргумент имеет приоритет над конфигурацией. У `tasks_api.py` общие параметры указываются до подкоманды. Аргументы процесса могут быть видны другим процессам на компьютере.

**Загрузка TSV:** текущий файл содержит только входные данные и не задаёт ограничение самопроверки. Для ограничения доступа используйте `unavailable_for` в API-заданиях из JSONL. Загрузчик отклонил заголовок `UNAVAILABLE_FOR`; корректный формат TSV пока не установлен.

## Экзамен

`configs/exam.tsv` содержит 10 заданий. Для фотографий `762719232` и `762720003` рамки заменены случайными; их корректность не проверялась. Эталонные вердикты не добавлены, проверка экзамена ручная.

Перед загрузкой проверьте целевой пул, отсутствие дубликатов и параметры распределения по страницам. Загрузка отдельных заданий через API сама по себе не гарантирует нужное число фотографий на странице. В `unavailable_for` входят авторы ответов из указанных при подготовке пулов; авторов из других пулов и ответов `REJECTED` этот список не учитывает.
