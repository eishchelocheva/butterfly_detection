# Модели для обнаружения бабочек на фотографиях

В ноутбуке `models_final.ipynb` сравниваются GroundingDINO tiny, OWLv2 base и Qwen3-VL-2B-Instruct. Модели ищут взрослых дневных и ночных бабочек по текстовому запросу. Используются готовые веса Hugging Face. Для оценки берутся 400 фотографий из golden set. Посылка формируется на отдельном наборе из 400 фотографий Контеста.

## Файлы

| Файл | Назначение |
| --- | --- |
| `models_final.ipynb` | Прогоны моделей, оценка, графики и формирование посылки |
| `leaderboard.csv` | Метрики 11 конфигураций: Precision, Recall, F1@IoU 0.5 и 0.75, время, ошибки и ложные рамки |
| `evaluation_predictions/` | Предсказания на golden set. По пять JSONL для GroundingDINO и OWLv2 и один для Qwen |
| `metrics_by_category.csv` | Метрики трёх моделей по семи категориям фотографий |
| `build_metrics_by_category.py` | Скрипт для повторного расчёта метрик по категориям |
| `submission.jsonl` | Готовая посылка OWLv2 на 400 фото Контеста |

Входные файлы, которые ноутбук читает из папки `ROOT` на Google Drive:

| Файл | Назначение |

## Метрики по категориям

Помимо общих результатов рассчитаны метрики для
семи категорий фотографий.

Результаты находятся в
[`metrics_by_category.csv`](metrics_by_category.csv).

Метрики рассчитываются из сохранённых JSONL-предсказаний
и итоговой разметки Golden Set.

Для повторного расчёта выполните из корня репозитория:

```bash
python3 models/build_metrics_by_category.py
```

Повторно запускать модели не требуется.

## Запуск в Google Colab

1. Откройте ноутбук в Colab, выберите среду с GPU и выполните ячейку установки зависимостей.
2. Поместите входные файлы на Google Drive в папку `Разметка`, сохранив вложенные пути. Если файлы лежат в другой папке, измените `ROOT` в ячейке данных. Golden set и манифест команды соединяются по `photo_id`.
3. Выполните ячейки по порядку до таблицы и графиков включительно. После каждого прогона ноутбук записывает предсказания модели в `evaluation_predictions`, по одной строке на фото.
4. Для воспроизведения посылки задайте в последней ячейке `CONTEST_MODEL = 'owl'` и `CONTEST_CONFIDENCE = 0.50`. Выполните её в том же сеансе после оценки OWLv2. Ноутбук сохранит `model_artifacts/submission.jsonl` и `model_artifacts/selection.json`.

## Оценка и результаты

На каждой фотографии предсказанные рамки сопоставляются с эталонными один к одному. Код отдельно находит максимальное число пар при IoU 0.50 и 0.75. Метрики считаются по суммарным TP, FP и FN для всех фотографий. Порог 0.75 строже проверяет точность рамок. Для графиков и выбора модели используется IoU 0.50.

Для GroundingDINO и OWLv2 проверены пороги уверенности `0.10`, `0.15`, `0.25`, `0.35` и `0.50`. Сравнение проводится на одних и тех же кандидатах, с NMS при IoU 0.5. Qwen генерирует координаты в JSON и оценивается без порога уверенности.

Если первый ответ Qwen не разбирается как JSON, модель получает более короткий запрос и уменьшенную копию фото. Если повтор не помог, в файле оценки для этого фото записываются `boxes: null` и причина ошибки. 

| Модель | Порог уверенности | F1 при IoU 0.50 | F1 при IoU 0.75 | Ошибки обработки |
| --- | ---: | ---: | ---: | ---: |
| GroundingDINO tiny | 0.35 | 0.772 | 0.673 | 0 |
| OWLv2 base | 0.50 | 0.818 | 0.530 | 0 |
| Qwen3-VL-2B-Instruct | — | 0.870 | 0.750 | 1 |

В таблице показана лучшая конфигурация каждой модели по F1 при IoU 0.50. Для Контеста выбрана **OWLv2 с порогом 0.50**. Среди конфигураций без ошибок обработки у OWLv2 наибольший F1 при IoU 0.50. При этом Qwen показала более высокий F1 в целом, но допустила одну ошибку обработки. OWLv2 также создала меньше ложных рамок на фотографиях без бабочек: 26 против 78 у Qwen, и обрабатывала фотографии быстрее: 1.03 секунды против 4.30 секунды. Поэтому OWLv2 была выбрана как компромисс между качеством, скоростью и надёжностью. У Qwen на фото `762560238` даже после повтора остался невалидный JSON.

Посылка содержит 400 строк UTF-8, по одной на каждый ID Контеста. В строке записываются `photo_id`, `photo_url`, список `boxes` и `error: null`. Координаты рамок `left`, `top`, `width`, `height` заданы в долях от ширины и высоты исходного фото. Последняя ячейка ноутбука создаёт `model_artifacts/selection.json` с версией весов, текстовым запросом и параметрами выбранного прогона. Этот файл пока не включён в репозиторий.
