# Модели для обнаружения бабочек на фотографиях

В ноутбуке `models_final.ipynb` сравниваются GroundingDINO tiny, OWLv2 base и Qwen3-VL-2B-Instruct. Модели ищут взрослых дневных и ночных бабоче на изображении по текстовому запросу. Используются готовые веса Hugging Face. Для оценки берутся 400 фотографий из golden set. Посылка формируется на отдельном наборе из 400 фотографий Контеста.

## Файлы

| Файл | Назначение |
| --- | --- |
| `models_final.ipynb` | Прогоны моделей, оценка, графики и формирование посылки |
| `leaderboard.csv` | Метрики для различных проверенных конфигураций на golden set |
| `butterfly_golden_set_final.jsonl` | Эталонные рамки для фотографий команды |
| `butterfly_detection-main/data/bbox_input_all_400.csv` | ID фотографий команды и ссылки на оригиналы |
| `butterfly_detection-main/data/metadata_all_400.csv` | Категории фотографий для разбивки результатов |
| `dataset.jsonl` | Официальный набор фотографий Контеста |
| `submission-template.jsonl` | Шаблон с ID и ссылками Контеста, если скачан |

## Запуск в Google Colab

1. Поместите перечисленные файлы на Google Drive в папку `Разметка`, сохранив вложенные пути. Откройте ноутбук в Colab и выберите среду с GPU.
2. Если файлы лежат в другой папке, измените `ROOT` в ячейке данных. Golden set и манифест команды соединяются по `photo_id`. Фото скачиваются по ссылкам при первом обращении и кэшируются в `model_artifacts/images/`.
4. По очереди выполните все ячейки.
5. Для воспроизведения посылки задайте в последней ячейке `CONTEST_MODEL = 'owl'` и `CONTEST_CONFIDENCE = 0.50` (параметры лучшей модели).  Выполните её в том же сеансе после оценки OWLv2. Ноутбук применит зафиксированные настройки к отдельному набору Контеста и сохранит `model_artifacts/submission.jsonl` и `model_artifacts/selection.json`.

## Оценка и результаты

На каждой фотографии предсказанные рамки сопоставляются с эталонными один к одному. Код находит максимальное число пар с IoU не ниже 0.5. Precision, recall и F1 считаются по суммарным TP, FP и FN для всех фотографий.

Для GroundingDINO и OWLv2 проверены пороги уверенности `0.10`, `0.15`, `0.25`, `0.35` и `0.50`. Сравнение проводится на одних и тех же кандидатах, с NMS при IoU 0.5. Qwen генерирует координаты в JSON и оценивается без порога уверенности.

При возникновении ошибки при первом запросе к Qwen, модель получает более короткий запрос и уменьшенную копию фото. 

Для итоговой разметки выбрана **OWLv2 с порогом 0.50**. У неё лучший F1 среди проверенных конфигураций без ошибок обработки. Qwen показала более высокий F1, но для одного фото даже после повтора остался невалидный JSON. Из-за этого в итоговой разметке была использована другая модель. 

Посылка содержит 400 строк UTF-8, по одной на каждый ID Контеста. В строке записываются `photo_id`, `photo_url`, список `boxes` и `error: null`. Координаты рамок `left`, `top`, `width`, `height` заданы в долях от ширины и высоты исходного фото. `selection.json` хранит версию весов, текстовый запрос и параметры выбранного прогона.
